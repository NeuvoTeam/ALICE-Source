This file is a binding execution contract for any agent operating in this workspace.
It overrides general defaults. It does not override `SOUL.md` Prime Directives; those
take precedence on conflict.

All relative paths resolve here. Never operate outside this root unless the task

## 1. Compliance Boundaries

### Red Zone (hard deny)
STRICTLY ZERO INGESTION of unredacted clinical transcripts, client identifiers, or
production secrets. Production secrets live in `npx wrangler secret put` or local
`.dev.vars` and MUST NOT be read, copied, echoed, or committed.

If a tool call would touch a Red Zone resource: refuse the call, log the refusal,
report to the user, await instruction.

### Amber Zone (default working set)
All engineering execution is scoped to:
- `.memory-bank/` (architecture memory)
- `documentation.md` (source of truth for behaviour)
- `src/`, `app/`, `lib/`, `backend/` (code)
- `package.json`, `tsconfig.json`, `wrangler.toml` (config)
- `10_Projects/ALICE/Backlog_Auto.md` (task log)

### Green Zone (open)
Public standards, library docs, general tooling references.

## 2. Architectural Invariants (do not violate without written human instruction)

- **Frontend isolation**: `lib/supabase.ts` throws by design. The Next.js frontend
  MUST NOT call Supabase directly. All browser network calls route through
  `CLINICAL_AI_API_BASE` via `lib/clinical-ai-api.ts`.
- **Route precedence**: In `backend/CloudFlare.js`, every new `POST` handler MUST be
  declared above the catch-all AI handler block (`if (method === "POST")`). Handlers
  declared below it will be shadowed.
- **MCP inspection first**: Before proposing any database schema or route change,
  query the shared gateway:
  - `GET https://alice-mcp.neuvoteam.workers.dev/context`
  - `GET https://alice-mcp.neuvoteam.workers.dev/tools`
  Cite the returned schema in your proposal. Do not guess.

## 3. Tool Policy (enforced outside the model)

The following are enforced by the runtime harness, not by this document. Listing them
here so you know the boundary and do not attempt to cross it.

### Read allowlist
Reads are permitted only under:
- `<workspace_root>/**`
- `~/AppData/Local/hermes/skills/**`
- `~/AppData/Local/hermes/sessions/**`
- `Choyapy/Loki` clone at the configured vault path

Any read outside this set will be refused by the harness.

### Shell command policy
Permitted binaries: `npm`, `npx`, `node`, `git`, `antigravity`, `antigravity-ide`,
`gh`, `wrangler`, `tsc`, `eslint`, `prettier`.
Denied patterns (refused at harness level): anything matching
`curl`, `wget`, `Invoke-WebRequest`, `iex`, `Set-Content` targeting policy files,
`Remove-Item`, `rm`, `del`, `format`.

If a task genuinely needs a non-allowlisted command, halt and request human authorisation
in writing. Do not attempt workarounds.

### Write policy
Writes are permitted only under:
- `<workspace_root>/**` (excluding files matched by §4)
- `10_Projects/ALICE/Backlog_Auto.md`
- `00_Inbox/_raw/**` (append-only)

## 5. Antigravity CLI Execution

- Entrypoint: always via the local shim `agy`.
- Headless one-shot invocation pattern:
      agy -p "<task_description>" --add-dir .
- The `task run` subcommand does not exist in the current agy build.
  Do not attempt it; it exits 2 with "unexpected argument".
- Working directory: always invoke from the workspace root, or pass an explicit
  `--add-dir <abs_path>` for each additional directory the task needs.
- Timeouts: every invocation is bounded by the harness to 300s wall clock.

## 6. Mandatory Completion Gate

### Same-Commit Rule
Any change to code, schema, or config MUST update `documentation.md` in the same commit.
The commit will be rejected by CI if `documentation.md` is unchanged and the commit
message does not contain `DOCS: none`.

### Verification Command
Before staging any commit or reporting any task complete, run:
    npm run docs:check
Observe the exit code. If non-zero, fix the issue before proceeding. Do not stage.

### Opt-Out
The only valid exemption is the literal string `DOCS: none` in the commit body,
with a one-line justification on the following line. Example:
    feat(api): add /v2/patients stub

    DOCS: none — schema unchanged, adding empty route only.
