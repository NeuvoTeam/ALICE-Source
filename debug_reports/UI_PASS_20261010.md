# UI pass — visual evidence (2026-10-10)

Task: kanban `t_6894e0a5` — modality selection to dropdown + checkboxes, plus a bounded
presentation-only pass over the dashboard surfaces. Coding agent: Antigravity CLI (`agy`),
model `gemini-3.1-pro-high` (non-Claude, per the operator constraint).

Every screen in the app sits behind `AuthGuard` + the live Worker API, so the affected
components were rendered in an offline harness instead of driving the real app (no
production credentials were used — Red Zone).

## Harness

Two throwaway harnesses, built outside the repo, bundled with the repo's own `esbuild`
against the **compiled Tailwind output from `npm run build`** (so the classes under test are
the ones the app actually ships):

- `modality-harness.html` — two `ModalitySelector` instances, 2 selected and 3 selected.
- `shell-harness.html` — the real `DashboardSidebar` (zustand store seeded with a client,
  2 cases and 2 sessions) next to the real `VignetteGenerator` step 1, with `window.fetch`
  stubbed to reject so nothing touches the Worker.

Harness sources: `%LOCALAPPDATA%\hermes\profiles\kuro\cache\scratch\`
(`modality-harness-entry.tsx`, `shell-harness-entry.tsx`, `alice-compiled.css`,
plus the SSR smoke test `ssr-modality-smoke.tsx`).
